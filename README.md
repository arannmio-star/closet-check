# 옷장체크 (독립 실행판)

내 옷과 신발을 사진으로 등록하고, 새 상품을 사기 전에 이미 비슷한 옷이 있는지 확인하는 앱입니다.
Claude 같은 AI 서비스나 서버 없이, 모든 계산과 저장이 폰 안에서 이루어집니다. 인터넷이 없어도 실행됩니다.

## 들어 있는 것

| 위치 | 내용 |
|---|---|
| `docs/` | 앱 본체. 이 폴더 내용을 웹에 올리면 폰에 설치할 수 있습니다. |
| `docs/index.html` | 앱 화면과 기능 전체 |
| `docs/manifest.webmanifest`, `docs/icons/` | 설치용 이름과 아이콘 |
| `docs/sw.js` | 오프라인 실행용 저장 파일 |
| `android/`, `.github/`, `package.json`, `capacitor.config.json` | APK로 만들 때 쓰는 파일 (선택, 방법 B) |

## 방법 A. 폰에 웹앱으로 설치하기 (권장)

앱 설치는 주소가 `https://`로 시작하는 곳에 올려야 가능합니다. 무료인 GitHub Pages를 쓰는 방법입니다.
아래 화면 이름은 GitHub가 바꿀 수 있어서 조금 다를 수 있습니다.

1. github.com에 가입하거나 로그인합니다.
2. 오른쪽 위 **+** → **New repository**를 누르고, 이름을 `closet-check`로 정하고 **Public**을 선택한 뒤 만듭니다.
3. 만들어진 화면에서 **uploading an existing file**을 누르고, 이 압축 파일 안의 모든 파일과 폴더(`docs` 폴더 포함)를 끌어다 놓은 뒤 **Commit changes**를 누릅니다.
4. 저장소의 **Settings → Pages**로 이동해 **Branch**를 `main`, 폴더를 `/docs`로 선택하고 **Save**를 누릅니다.
5. 1~2분 뒤 같은 화면에 `https://사용자이름.github.io/closet-check/` 주소가 나타납니다.
6. 폰 Chrome에서 그 주소를 열고, 메뉴(⋮) → **앱 설치** 또는 **홈 화면에 추가**를 누릅니다.

공개 저장소에는 앱 코드와 주소만 보입니다. 등록한 옷 사진과 기록은 폰 안에만 저장되고 올라가지 않습니다.

## 기존 데이터 옮기기

이전에 Claude 링크로 쓰던 옷장 데이터가 있으면:
1. 이전 앱에서 **설정(톱니) → 백업 파일 저장**
2. 새 앱에서 **설정 → 백업 파일 선택**으로 불러오기

새 앱에서 처음 연 뒤에는, 브라우저에서 등록한 데이터가 설치한 앱에서도 보이는지 한 번 확인하세요. 보이지 않으면 같은 방법으로 백업 파일을 옮기면 됩니다.

## 꼭 지켜야 할 것

- 데이터는 이 폰에만 있습니다. 앱 데이터를 지우거나, 앱을 삭제하거나, 폰을 바꾸면 사라집니다.
- 옷을 여러 벌 등록한 날마다 **설정 → 백업 파일 저장**으로 백업해 두세요.

## 일치도 계산 방식과 한계

후보 사진과 내 옷 사진에서 배경을 걷어내고 세 가지를 비교해 0~100%로 계산합니다.
- 색상: 평균 색과 색 분포
- 모양: 윤곽, 가로세로 비율, 길이감
- 무늬·질감: 결 변화의 세기

같은 사진이면 항상 같은 값이 나옵니다. 다만 소재, 단추·칼라 같은 작은 디테일은 비교하지 못합니다. 정확도를 높이려면 다음처럼 찍으세요.
- 옷걸이에 걸거나 평평하게 펼쳐서 정면으로 찍기
- 단색 배경 앞에서, 옷이 화면에 꽉 차게
- 모든 옷을 비슷한 밝기와 거리로

설정의 **같은 옷으로 볼 기준**(기본 80%)으로 판정 기준을 바꿀 수 있습니다. 같은 옷인데 낮게 나오면 기준을 낮추고, 다른 옷인데 높게 나오면 올려 보세요.

## 앱을 수정해서 다시 올릴 때

`docs/sw.js` 맨 위의 `VERSION` 숫자를 올린 뒤 파일을 교체해 올리세요. 올리지 않으면 폰에 예전 버전이 남을 수 있습니다.

## 방법 B. APK 파일로 폰에 직접 설치하기 (시험하지 않음)

`android/` 폴더에 안드로이드 앱 프로젝트가, `.github/workflows/build-apk.yml`에 APK를 자동으로 만드는 설정이 들어 있습니다.
**이 환경에서는 APK를 실제로 만들어 볼 수 없었으므로, 빌드와 폰 설치는 아직 한 번도 시험하지 않았습니다.** 빌드가 실패하면 실패 화면의 오류 내용을 알려 주세요.

1. 방법 A의 2~3단계처럼 저장소를 만들고, 이 압축 파일 안의 **모든 파일과 폴더**(`android`, `docs`, `.github` 포함)를 올립니다.
   - `.github` 폴더는 이름이 점(.)으로 시작해 파일 선택 창에서 안 보일 수 있습니다. 폴더 째로 끌어다 놓으세요. 안 되면 저장소에서 **Add file → Create new file**을 누르고 이름 칸에 `.github/workflows/build-apk.yml`을 입력한 뒤, 그 파일 내용을 붙여 넣으세요.
2. 저장소의 **Actions** 탭 → 왼쪽 **Build APK** → **Run workflow**를 누릅니다. (처음에는 Actions를 켜라는 안내가 나올 수 있습니다.) 올리자마자 자동으로 시작되기도 합니다.
3. 5~10분 뒤 초록 체크가 뜨면 그 실행을 눌러 맨 아래 **Artifacts**의 `closet-check-apk`를 내려받습니다. (zip 안에 `app-debug.apk`가 있습니다.)
4. 폰으로 apk를 옮겨(또는 폰에서 직접 내려받아) 누르면 설치 화면이 뜹니다. 안드로이드가 "출처를 알 수 없는 앱" 허용을 물으면 그 앱(크롬, 파일 앱 등)에 한해 허용하세요. 개발용(debug) 서명이라 Play 보호 경고가 나올 수 있습니다.

APK 앱에서의 차이:
- 백업 파일 저장은 폰의 공유 창이 열립니다. 거기서 드라이브, 카카오톡 나에게 보내기, 파일 저장 등을 고르세요.
- 웹앱(방법 A)과 APK 앱은 저장소가 서로 달라 데이터가 따로 있습니다. 옮길 때는 백업 파일로 옮기세요.
- 앱을 고쳐 다시 만들면 같은 서명이어서 덮어 설치되고 데이터가 유지됩니다. 단, 다른 컴퓨터에서 만든 APK는 서명이 달라 덮어 설치되지 않을 수 있으니, 업데이트 전에 백업하세요.

PC에서 직접 만들려면 Node.js, Java 21, Android Studio가 필요합니다: `npm install` → `npx cap sync android` → `npx cap open android` → Build APK.
